# Validated release to Power BI

The local DAG ends with Gold quality → Power BI export → final pipeline validation → successful release pointer. The export task creates a pending local refresh-request file. Stage 13 creates a validated local request; the pointer advances only after that task succeeds. Nothing contacts Power BI Service. Existing saved Desktop projects and Gold/ML latest pointers are preserved.

Each release has three coherent import paths: `GoldDataPath`, `SyntheticGoldDataPath`, and `MLGoldDataPath`. Its manifest, CSV types, Gold quality sibling layout and exact integer-key validation support the existing report. DEV can include the prior champion's unchanged offline Model Performance table with its original test periods. TEST fixture exports contain synthetic baseline scores, not fabricated model-validation metrics. Do not label TEST output a full validated production semantic model.

Option A is Import through governed Databricks SQL views over one successfully published Gold build. It suits the small snapshot and isolates interactive querying from warehouse latency; freshness depends on refresh scheduling. Local files need an accessible service refresh path/gateway arrangement if later hosted. Option B is DirectQuery through a governed SQL Warehouse, which can support lower data latency but makes warehouse cost, query behavior, concurrency and network availability part of the report experience. Benchmark actual workloads and security; neither option is universally better.

A future refresh dispatcher should verify the completed release ID, acquire a semantic-model refresh lease, request a refresh using an approved service identity, record the request ID and poll for terminal success/failure with bounded retries. Token values must never enter request manifests. A failed refresh leaves the previous successful report available and alerts operations. Do not blindly retry ambiguous POST timeouts without reconciling whether a refresh was already accepted. Enhanced refresh can use a transactional commit to avoid partial-model visibility; it has capacity/permission prerequisites. See [Microsoft's refresh API documentation](https://learn.microsoft.com/en-us/power-bi/connect-data/asynchronous-refresh/).

Dataset lifecycle: Development → Validated → Certified → Deprecated. Certification requires passing contracts/quality/reconciliation, documented owner and business definitions, security/export review and an approved release. It is a governance decision, not a boolean generated from a successful script. Roll back report/model releases and the selected Gold view/pointer as a coordinated version, preserving evidence.

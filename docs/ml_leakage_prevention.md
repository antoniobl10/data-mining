# Point-in-time and label contracts

**SYNTHETIC DEMO MODEL.** All feature sources use strict `< feature_cutoff_date`. All labels use `[label_window_start, label_window_end)`. No feature source can use its final-state snapshot value as historical truth.

Monthly customer snapshots span January 2025–August 2026. The scoring cutoff is October 1, 2026, using history through September 30. Historical monthly cutoffs are deliberately conservative for campaign rows: the first day of the launch month, rather than the later launch day. Campaign context known at launch (channel/type) is allowed; no conversion response is available to features at that point. Labels start at the actual launch date and cover 30 days. Only fully matured label windows enter training.

Historical products derive ownership from start and end dates, ignoring final `is_active`. Payroll derives prior activation from `payroll_start_date`, not final payroll status. Monthly payroll amount and final months-with-payroll are excluded. Service eligibility is usable only after a dated offer; future eligibility is not backfilled. Service counts mean **ever activated before cutoff**, because deactivation timestamps are absent; final `active_status` and `monthly_usage_count` are excluded. No service-specific browsing is inferred from generic `service_view` events.

Campaign opens/clicks have no availability timestamp, so neither prior open rates nor CTR is reconstructed. Historical conversion rate uses only previously matured launch cohorts and conversions dated inside their 30-day windows. Conversion recency requires a known conversion strictly before cutoff. Satisfaction uses dated surveys; resolution is excluded because its resolution timestamp is unknown.

Original age, tenure, balances, estimated salary, credit score and customer value have no historical versions. They are review-required for modeling and excluded from all historical predictors. Current value is allowed only as an explicitly current, non-model business priority factor after scoring. Country, gender and age bands are audit-only. The final Customer 360 engagement/primary scores are never backfilled: the feature layer recomputes digital engagement and a payroll-free relationship score from available history.

Train, validation and test split on unique prediction months, not rows. The nominal fractions are 60/20/20; purge rules reduce actual row counts. Training labels must end no later than the next partition's first prediction cutoff. Validation is divided into an early calibration slice and a later model-selection slice, with an additional label-end purge. Internal cross-validation uses expanding date blocks with the same purge. This removes late-month campaign rows at boundaries, intentionally.

The same customers may recur across chronological partitions: evaluation asks about later behavior of the existing cohort. It does **not** establish generalization to unseen customers. Customers and the source cohort were selected from final available data, so historical cohort membership is a synthetic reconstruction assumption. True historical customer onboarding/exit and bitemporal availability are absent.

Preprocessing (median imputation, missingness indicators, scaling and categorical encoding) is fitted only inside each training fold. Class weights affect training only. No SMOTE, oversampling, validation balancing or test tuning occurs. Sigmoid calibration fits only the early validation slice and is retained only if later validation Brier score improves. At least ten calibration positives are required. Isotonic is intentionally omitted for these small positive counts. Test threshold sensitivity is descriptive, never selection input.

The initial campaign run encountered an explainability interface error after evaluation. That failed attempt is preserved locally; the corrected run repeated the same deterministic candidate search and selected the same classifier. No test result was used to change the feature policy, algorithms, tuning ranges or champion-selection rule. Final completed runs evaluate only the selected champion on held-out test data. Repeat experimentation on this test set would require a fresh holdout.

Tests mutate/remove future events, alter final snapshot fields, check cutoff equality, future labels, purge boundaries, allowlists, serialization and eligibility. These establish the implemented contracts; they cannot establish that synthetic source timestamps represent real-world availability.

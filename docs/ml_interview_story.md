# Interview explanation — SYNTHETIC DEMO MODEL

## 90 seconds

“I extended an existing Medallion banking analytics project with a predictive layer on synthetic behavior. The main engineering challenge was point-in-time correctness: several Customer 360 fields were final snapshots, so I reconstructed historical features from dated events and excluded fields whose availability could not be established. I compared a constant baseline, logistic regression, random forest and histogram gradient boosting using purged temporal splits. I kept preprocessing inside sklearn pipelines, tracked runs locally with MLflow and versioned selected model packages. Batch scoring writes customer scores and an eligibility-gated Next Best Action mart back to Gold, with separate Power BI pages for scores, actions and offline performance. The results were weak, and payroll selected the baseline. I kept that finding visible rather than presenting synthetic metrics as a real banking success. The project demonstrates a reproducible workflow; real effectiveness would require governed data and randomized experiments.”

## Three-minute technical explanation

Start with the existing original Gold star and synthetic behavioral domain. The feature grain is customer/date. Before each cutoff, aggregate 7/30-day events, 90-day campaigns, dated products, prior payroll starts, offered/activated services and dated surveys. Never copy final Customer 360 engagement or current value backward. Exclude opens/clicks and resolved status because response timestamps are missing. Historical service state means ever activated because deactivation history is unavailable.

Define 30-day future targets separately: campaign conversion following launch, digital inactivity for the churn proxy, first payroll start in the no-payroll current-account population, and travel activation for eligible offered customers without prior activation. Split on months, purge label overlaps, and use expanding-window inner folds. Fit imputers, missing indicators, scaling and encoders inside training pipelines. Compare three model families plus a constant prior, use training-only balanced weights, and choose small hyperparameter grids through internal validation. Fit optional sigmoid on an early validation slice; accept it only if later validation Brier improves. Select champions from validation ranking and stability, then inspect the held-out test once per successful run.

Explain selected models with validation permutation importance, coefficients where applicable, and explicitly non-causal local perturbations. SHAP is optional and absent in the verified environment, so do not call those perturbations SHAP. Persist pipelines, calibration, features, thresholds, source/config/code digests and MLflow IDs. Batch score only compatible feature builds, preserve nulls for ineligible populations, apply consent/ownership gates and export immutable predictions plus an SQL opportunity mart. Compare distributions and missingness, but require matured labels for concept-drift claims.

## Five-minute architecture explanation

Use the 90-second narrative, then spend one minute on availability contracts and examples of rejected snapshot leakage. Spend one minute on chronological splitting, purging, sparse positive labels and why PR-AUC/lift matter more than accuracy. Spend one minute on local MLflow, selected registry versions, preprocessing persistence, immutable batch publications and the Power BI separation between offline evaluation and business KPIs. Finish with one minute on eligibility-gated action scores, responsible-use audits, weak results and productionization.

Emphasize that an engineering pipeline can work while a model fails its business objective. Campaign and travel top-decile results do not demonstrate useful targeting; payroll's constant baseline has no personalized ranking. Calibration and non-sensitive allowlists do not establish deployment safety or fairness. Next steps are better event-time histories and labels, an independent holdout, real consent and access controls, governed registry promotion, orchestration/CI/CD, drift monitoring with matured labels, and randomized treatment/control experiments to measure causal effectiveness.

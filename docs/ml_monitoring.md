# Monitoring and drift design

**SYNTHETIC DEMO MODEL.** `ml/reports/drift_report` contains per-feature missing rates, training-reference quantile PSI, KS statistic and score summaries. Quantile bins come only from the reference distribution with infinite outer edges; duplicates are removed. Constant references can produce a single bin, so PSI alone can miss changes; inspect KS and raw distributions. Epsilon smoothing stabilizes zero bins and makes PSI sensitive to bin choices. These are descriptive diagnostics, not universal pass/fail tests.

The baseline is each champion's training period; current is the configured scoring population after eligibility. Eligibility and historical cohort changes can themselves change distributions. Compare like populations before escalating. Missingness and score drift can reveal broken inputs even when labels have not matured. KS p-values are intentionally omitted because repeated-customer dependence invalidates a simple iid significance interpretation.

**Data drift** changes the input distribution. **Concept drift** changes the relationship between features and target. Score changes alone do not establish concept drift. Record feature version, scoring date, eligible counts, model version and target horizon. When future labels mature, join on observation/customer/date, validate outcome completeness and recompute PR-AUC, Brier, capacity recall/lift and group audits by scoring cohort. A future absence of labels is not a negative outcome. Never silently overwrite the initial held-out evaluation.

Production alerts need business-approved thresholds, seasonality baselines and minimum sample sizes. An analyst should distinguish source-schema failure, changed consent/eligibility, population drift and model deterioration. Rollback chooses a prior archived validated version; retraining becomes a new Candidate with a fresh holdout. This phase supplies diagnostics and the design, not a running production alerting or automatic retraining service.

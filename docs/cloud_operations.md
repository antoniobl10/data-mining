# Azure storage, operations, costs and recovery reference

Logical ADLS organization: `/bronze/<domain>/batch_id=...`, `/silver/<domain>/...`, `/gold/customer_360/`, `/ml/features/prediction_date=...`, `/ml/predictions/scoring_date=...`, `/audit/` and `/quality/`. Supply real account/container names through approved deployment configuration. Use Delta for governed mutable tables; retain raw source/event evidence separately under an approved retention policy.

Unity Catalog provides the conceptual ownership/access/discovery/lineage boundary across `banking_dev/test/prod`. Use storage credentials/external locations and identities aligned with environment isolation. Azure Key Vault supplies secrets only when managed/workload identity cannot avoid them. Azure Monitor can consume sanitized operational metrics and alerts. GitHub Actions supplies reviewed code/config/releases; it does not replace data-plane authorization.

For a small batch, Pandas remains proportionate; Spark becomes useful for distributed event histories, joins and scalable feature preparation. Prefer governed job compute with suitable autoscaling/termination over a permanently idle all-purpose cluster, subject to actual organization policies. Size SQL Warehouses from measured report concurrency/latency. Batch reduces operational complexity; streaming is justified when timely engagement/intervention creates enough value to pay for continuous compute and state management.

Delta schema enforcement and reviewed MERGE keys support reliable changes. Use `OPTIMIZE`/layout clustering only after file-size/query evidence justifies maintenance. Z-ORDER can help selected lookup/range access patterns where supported; it is not a universal extra step. Set `VACUUM` retention only after recovery, concurrent-reader, audit and privacy requirements are understood. No Delta maintenance commands were executed on a workspace. Benchmark larger data before choosing partition keys; avoid high-cardinality customer partitions.

Design targets, **not achieved SLAs**: daily customer publication before 07:00 Europe/Berlin, 99% successful scheduled releases over a defined window, critical Gold freshness under 24 hours, and Power BI refresh only after validation. Define start/end points and exclusions before measuring. The frozen demo fails real-time event freshness, so it cannot establish these SLOs.

Disaster recovery remains proportionate: versioned code/config, immutable data/model artifacts, protected backups and documented restore tests. Select storage redundancy, RPO/RTO and cross-region requirements with the owner. Back up the local audit DB together with run/checkpoint manifests; back up model artifacts and registry together. Cloud recovery needs approved storage/Delta retention, catalog permissions, registry access and the compatible semantic-model release. No enterprise DR exercise or Azure deployment was performed.

Future streaming flow: digital event producer → Azure Event Hubs/Kafka → Structured Streaming → replayable Delta Bronze → typed/deduplicated Silver → near-real-time engagement. Preserve ingestion/event timestamps, late-event policy, checkpoint ownership, schema contracts and idempotent sinks. Keep training features point-in-time correct even if serving becomes faster. No Kafka service is added to this portfolio.
